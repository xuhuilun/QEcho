# 提示词分组设计与实施计划

提示词分组沿用 `qecho.toml` 与现有启动脚本。`[agent].prompt` 定义全局系统提示词，`[agent].friends` 列出使用全局默认组的好友。用 `[[agent.prompt_groups]]` 定义一组可复用的提示词，设置 `name`、`friends` 和 `prompt`。在 `[agent.friend_prompts]` 按 QQ 号添加好友个人提示词。

```toml
[agent]
prompt = "自然回复，保持事实准确，不替我作承诺。"
friends = ["10000001"]
auto_start = true

[[agent.prompt_groups]]
name = "亲近好友"
friends = ["10000002", "10000003"]
prompt = "语气轻松，主动回应对方提到的细节。"

[agent.friend_prompts]
"10000002" = "称呼对方为小林，少用表情。"
```

生成回复时按全局提示词、所属组提示词、好友个人提示词顺序组成系统消息。全局约束适用于所有好友。称呼、语气等偏好有冲突时，优先采用更具体的好友设定，其次是组设定。未配置的层级跳过。使用原有联系人和消息历史隔离逻辑。

默认组和自定义组的好友列表共同构成自动回复范围。每位好友只能出现在一个列表，全部列表合计最多 500 位。组名和组提示词必填，组名不能重复。允许保留尚未分配好友的组。个人提示词只能为已列入范围的好友填写。配置读取时拒绝重复归组和未授权的个人提示词，错误不回显配置内容。启动时沿用原有实际好友核验、账号绑定和原子启用，校验失败保持停止。

分组成员由启动时加载的配置提供，提示词从文件初始化后可以在网页即时保存。保存持久化当前生效文本，并通过版本检查使旧待发任务失效。数据目录原先使用分组或个人提示词时，改用网页配置模式会先暂停，主人可在网页明确启动新规则。无需改变 SQLite 表结构，旧文件与旧网页数据保留兼容。实际生效的系统消息可通过已有联系人提示词预览接口核对。[网页提示词保存设计](live-prompt-editor.md)

实施顺序：先完善 TOML 校验和授权范围，再接入启动与回复生成；随后在状态页面展示分组，同步样例和部署文档。验收覆盖默认组、共享组、个人叠加、组间隔离、重复归组拒绝、个人提示词不得扩展授权，以及只填写自定义组也能启动。通过本机检查和 Windows、Ubuntu CI 后合并并推送。
