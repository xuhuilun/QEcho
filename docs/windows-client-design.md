# Windows 客户端与更新设计

首版提供 Windows x64 按用户安装的 EXE。PyInstaller 打包 Python、运行依赖和现有控制台资源，Inno Setup 负责安装、覆盖升级和卸载。客户端窗口提供配置文件、控制台和启动或退出入口。NapCat 单独安装并登录，QEcho 读取本地 TOML 后按配置启动。

安装目录和数据目录分开。客户端首次运行把配置样例复制到 `%LOCALAPPDATA%\QEcho\qecho.toml`。数据库默认保存在同目录的 `.data`，用户可在配置中调整。覆盖安装保留数据。客户端启动后可打开控制台，本地服务仅监听回环地址。

客户端启动后及每 15 分钟检查本仓库 GitHub Releases 的正式版本。发现新版时主动提示一次，用户可立即更新或稍后处理。更新下载限制在官方发布资产，检查文件大小、SHA-256 和 Windows 信任的 Authenticode 签名。安装包和正在运行的客户端须由同一证书签名。每个客户端以较高版本号为更新条件，发布预览不进入正式更新渠道。客户端退出期间在下一次启动检查。

校验成功后，客户端先停止代聊并关闭本地服务，等数据库释放后调用覆盖安装。安装器等待原客户端退出再写入程序文件。完成后自动打开新版客户端，用户点击「启动服务」恢复代聊。下载和校验失败时继续使用当前版本。

实施先复用本地服务生命周期，加入 Windows 窗口和更新检查，再在 Windows CI 打包、运行产物并验证覆盖安装。正式发布需要可信代码签名。CI 预览可独立验收安装，签名更新链路使用隔离的测试证书验证。
