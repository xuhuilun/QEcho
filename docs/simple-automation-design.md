# 极简 QQ 自动代聊设计

## 用户流程

部署并配置一次模型和本机 NapCat 连接 → 点击“登录 QQ”打开 NapCat 登录页 → 登录后自动同步 QQ 账号与好友 → 勾选部分好友 → 写一份统一 Agent 提示词 → 点击“开始自动回复”。页面提供始终可见的停止按钮。

用户已确认登录页可以单独打开，无需在 QEcho 内嵌二维码。QEcho 不实现 QQ 登录协议；NapCat 承担个人 QQ 登录。默认登录入口为 `http://127.0.0.1:6099/webui/qq_login`，允许在折叠设置修改。NapCat WebUI 自身可能要求认证或选择扫码选项。部署时仍需启用 NapCat OneBot HTTP 服务端及事件上报，打开登录页不会自动建立这些连接。

## 单页界面

保留本地管理令牌登录。登录后仅展示连接账号/登录按钮、同步按钮、可搜索的好友复选列表、一份统一提示词、开始/停止按钮和少量最近运行状态。模型和桥接参数放入折叠设置。首页移除三栏聊天、模拟器、逐条草稿及多个人格字段；相关旧 API 和数据保持兼容。

当前提示词与选择在点击开始时一起生效；编辑期间显示未应用提示。同步好友不自动授权。启动后默认对所选好友自动回复，不要求每条确认。停止不等待模型、账号查询或会话锁。

## API

- `GET /api/automation`：返回 `running`、`account_id`、`selected_ids`（QQ 号）、`prompt`、`revision`、`model_ready`、`login_url`、`recent`（最近 8 条回复的联系人、状态和错误摘要，不含密钥）。
- `POST /api/qq/sync`：查询 OneBot 登录账号与好友，自动绑定账号，返回上述状态加 `friends: [{qq_id, name}]`。
- `POST /api/automation/start`：请求 `{qq_ids: ["..."], prompt: "...", expected_revision: 1}`，验证后原子更新完整授权名单和统一提示词并开始自动回复，返回当前状态。
- `POST /api/automation/stop`：无网络等待，立即暂停并取消未发送回复，返回当前状态。
- 现有设置 API 用于模型、桥接地址/token，以及新增 `bridge_login_url`；密钥仍只写不读。

管理接口仍使用独立 Bearer 管理令牌。事件签名和已有 OneBot 事件入口保持不变。

## 数据与安全边界

保持单实例单 QQ 账号。登录账号首次自动填入设置；存在真实 QQ 会话时发现换号，暂停并要求使用独立数据目录，不能复用旧账号历史。好友范围以桥接实际好友列表验证，不信任客户端任意 QQ 号。

开始操作先检查客户端版本并暂停旧自动回复，再查询实际账号/好友和验证模型配置；异步验证完成后比较最新配置版本。验证失败保持暂停。成功后在单个 SQLite 事务内完成联系人授权、自动模式、统一提示词、版本递增和待发回复取消，最后启用全局开关。取消勾选的联系人失去发送权限。

新增内部 `simple_mode` 设置。极简启动使用统一提示词，忽略旧联系人中隐藏的人格/语气/补充指令，保留旧字段数据。模型上下文仍按联系人隔离。现有按入库顺序处理、生成后/身份查询后/发送前检查权限、未知发送结果不重试及本人回复接管机制继续使用。

## Windows 兼容

实例锁封装到 `qecho/runtime.py`：Windows 使用标准库 `msvcrt.locking`，其他系统使用 `fcntl.flock`。锁持有固定文件句柄，不删除锁文件；异常退出由操作系统释放。POSIX 权限限制继续保留，Windows 使用数据目录继承的 ACL，不把 chmod 模式声明成 Windows 权限保证。CI 增加 Windows 与 Linux 测试；只有实际通过才报告 Windows 验证结果。

## 验收

验证登录后账号/好友自动识别、仅选中好友自动回复、统一提示词生效、取消选择、启动失败保持暂停、并发停止、配置版本竞态、旧账号保护、旧人格不干扰新规则。浏览器验证极简单页、勾选/搜索/开始/停止、折叠设置及手机布局。使用模拟模型与桥接验证，不登录真实 QQ、不向真实联系人发送消息。
